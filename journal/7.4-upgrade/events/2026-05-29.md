## 2026-05-29 09:59

- Investigated native test failures from the Final version CI run (https://github.com/lucamolteni/quarkus/actions/runs/26581201635). All Hibernate Search native tests in Data6 failed with NullPointerException at HibernateOrmSearchSession.get() line 81, where session.getExtension() returned null.
- Compared against the CR1 CI run (https://github.com/lucamolteni/quarkus/actions/runs/26035922365#user-content-test-failures-job-76537750840) where all the same tests were green. The difference was Hibernate Search 8.4.0.CR1 vs 8.4.0.Final.
- Root cause: between CR1 and Final, Hibernate Search commit HSEARCH-5627 (https://github.com/hibernate/hibernate-search/commit/f70fd46f781b9c2834d21e6562d7b10adf978a0f) switched from an internal HibernateOrmSearchSessionHolder to ORM's new Extension SPI. The extension is discovered via ServiceLoader from META-INF/services/org.hibernate.engine.extension.spi.ExtensionIntegration. In native mode, Quarkus disables GraalVM's UseServiceLoaderFeature and requires explicit registration of service files. Without it, ServiceLoader finds nothing, the extension is never registered, and getExtension() returns null.
- Fixed by adding ExtensionIntegration to the SERVICE_PROVIDERS list in ClassNames.java, which tells Quarkus to include the service file in the native image.
- Rebased on upstream/main and force-pushed.
- commit: cb96fca5578 - Register ExtensionIntegration service provider for native mode
